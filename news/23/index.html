天择OS 3.2 发布：笔记命令升级、COC 自定义闪震与下载页修复

🗓 发布：2026-07-24 ✍ 作者：天择网

天择OS 3.2 是一次「细节 + 体验」的版本：笔记命令行新增多个子命令、笔记编号改为永不改变的固定编号、笔记保存占位与 AI 对话共用同一套轻量占位、COC 伤害计算器新增「自定义闪震数量」标签页、官网下载页终于能看到真实最新版。07-24 当日又追加了一次热修复——AI 悬浮窗里执行 clock/timer 5s/openurl/browser/store 等命令时不再报 Cannot read properties of null (reading 'appendChild')。

〇、07-24 热修复：AI 悬浮窗命令行报错

在 AI 悬浮窗（桌面版 Ctrl+1 唤起）里让 AI 执行「打开时钟」「5 秒倒计时」「打开这个网址」「打开浏览器」「打开软件商城」这类命令时，会集中报 Cannot read properties of null (reading 'appendChild') 错误。AI 对话窗口里这些命令能正常工作，因为主 OS 桌面有完整的 #windows 容器；悬浮窗是独立 Electron 窗口（float-chat.html），本来就不需要显示完整窗口，#windows 容器也未在 HTML 里提供。

本次修复同时做了三件事：

  • 在 float-chat.html 添加 id="windows" hidden 占位元素，让 WM.create 内部 $('#windows').appendChild(...) 不会执行在 null 上。
  • WM.create 检测 __tzFloatMode 走轻量路径：不绑定窗口拖拽/调整大小/标题栏菜单等交互，不调用 Taskbar.render 与全局 focus，窗口对象照常返回（让后续 w.body.querySelector(...) 仍能工作，倒计时按钮点击、浏览器标签页创建等依赖窗口 DOM 的逻辑不受影响）。
  • 涉及创建窗口的命令（clock、timer、openurl/go、browser home、open、store open、note）返回值统一追加「（窗口已创建，请在主 OS 桌面查看，悬浮窗无法显示完整窗口）」提示，AI 不会再误以为窗口已显示在悬浮窗中。

实测在 Electron 32 + Windows 11 环境下，9 个相关命令（clock、timer 5s、openurl https://example.com、browser tabs、browser home、open browser、store open、version、help）全部正常返回结果，不再有 null 报错。

一、笔记命令行升级

  • 新增子命令：note view 编号|标题 查看完整 Markdown 内容（不打开应用窗口），note edit 编号 文本 整体替换笔记（\n 表示换行），note undo 撤销最近一次 new/edit/append/del 改动（保留最近 30 步深拷贝快照）。
  • 固定编号：每篇笔记创建时分配一个永不改变的编号 no，从 1 开始按创建顺序递增，旧笔记自动迁移补齐。这样命令行长期引用「编号 3」永远指向同一篇笔记，不会因为新建/删除导致编号错位。
  • 保存占位修复：之前笔记保存时状态栏会出现"编辑中…"与"正在保存…"两条进度条并存，原因是「编辑中」文本和保存进度互不知道彼此的存在；现在改为与 AI 对话修复同源的 notes-saving-dot 轻量圆点占位（CSS 脉冲 + "正在保存…"），状态栏是唯一的进度反馈通道，干净不打架。

二、COC 伤害计算器：自定义闪震数量

第三个标签页「自定义闪震数量计算伤害」上线：输入雷电/地震数量，实时计算总伤害与逐瓶明细（先雷后震/先震后雷可切换），并显示 ⚡N + 🌍N 总法术空间占用。复用前两个标签页的 breakdownTable 与 toleranceHtml，结果格式与「最高伤害」「最少法术」完全一致，便于横向比较方案。

城墙三震不毁、四震必毁的规则在任意地震等级、任意 HP 下都成立（quakeHitDmg(4, H, lvl, true) = H - quakeDmg(3, H, lvl, true)，4 瓶时差值 = min(d, H-0.0001) - 0 = H）。

三、官网下载页：电脑端不再落后一个版本

老逻辑用 fetch(HEAD) 探测 GitHub Release 的下载 URL，但 github.com 的 release download 响应不带 CORS 头，跨域 HEAD 永远被浏览器拦截，导致电脑端永远回退 fallback、始终展示"落后一个版本"的提示。

改为调用 GitHub REST API（api.github.com 支持 CORS）：fetch('.../releases?per_page=30') 列出所有 release，自行按 tag 版本号排序取最大（API 返回顺序乱，不能取第一个），跳过 draft/prerelease，asset 名匹配 tianze-os-setup.*\.exe$ 且 state!='uploading'。30 分钟 localStorage 缓存（key tz_os_release_probe_v2）防未认证限流；API 失败回退写死最新版。

四、升级方式

网页版下次启动自动获取 3.2；桌面版请前往天择OS 入口下载 3.2 安装包覆盖安装。07-24 热修复已包含在 3.2.0 同一安装包中（不需要再次下载）。
